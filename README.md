# Danmaku Studio

**▶ [ブラウザで試す](https://maceknight.github.io/danmaku-studio/)**（インストール不要）

東方弾幕風 ph3 の弾幕を GUI で制作する統合エディタ。
映像編集ソフトのようにタイムライン上で演出を組み立て、`.dmk` を経由して ph3 スクリプトを出力する。

```
GUI → .dmk → AST → Danmakufu ph3 Script
```

## ローカルで起動

```bash
npm install --prefix danmaku-studio
```

```bash
npm run dev --prefix danmaku-studio
```

→ http://localhost:5183

## デプロイ

```bash
npm run deploy --prefix danmaku-studio
```

`dist` をビルドして `gh-pages` ブランチへ公開する。ビルド時のみ `base` が `/danmaku-studio/` になる（dev サーバーはルートのまま）。

## 設計原則

### パターン = クリップ

タイムラインの1行は**パターン**。グループは**エミッター**。
パターンが `開始時間 / 継続時間 / ループ / 優先度` を持ち、エミッターは位置・回転（とそのキーフレーム）を持つ。オブジェクトツリーとタイムラインは同じ階層を映す。

### キーフレーム方式とイベント方式の併用

| | 方式 | 編集場所 |
|---|---|---|
| エミッターの位置・回転 | キーフレーム補間 (linear / ease / hold) | グループ配下の ◆ レーン + プロパティ |
| 発射・レーザー・分裂・SE | イベントクリップ | タイムラインのクリップ |

エミッターを選択すると Position X / Y / Rotation の ◆ レーンが開く。◆ はドラッグで移動、Alt+クリックで削除。プレビューの移動ツールでエミッターをドラッグすると、アニメート済みチャンネルなら現在フレームにキーを打ち、そうでなければ静的座標を書き換える。

### 決定論的シミュレーション

フレーム N の弾幕は `(project, seed, N)` の純粋関数。乱数は seed 付き mulberry32 なので、スクラブしても同じフレームは必ず同じ絵になる。シークは 60F ごとのスナップショットから再生するため、逆方向スクラブでも全再計算は起きない。

### レイヤー分離

| モジュール | 依存 |
|---|---|
| `src/types/dmk.ts` | なし（`.dmk` スキーマ = 唯一の中間データ） |
| `src/engine/` | React も PixiJS も import しない |
| `src/render/stage.ts` | PixiJS のみ。Simulator の内部を知らない |
| `src/compiler/` | ph3 構文を知るのは `danmakufu.ts` だけ |
| `src/ui/` | 描画とシミュレーションに触れない |

## テーマ

ライト / ダークを切替可能。右上の ☀/🌙 か「設定」から変更でき、`localStorage` に保存される。プレビューのステージ配色（背景・グリッド・マーカー）も連動する。

## パターン

Circle / Spiral / Fan / Wave / Cross / Flower / N-Way / Random / Ring / Burst / Laser / Aim

各パターンは弾定義（ShotDataID・速度・加速度・角速度・寿命・サイズ・ブレンド・出現ディレイ・当たり半径）とモディファイア列を持つ。

弾は**色付きの外側ディスク + 白い内芯**の2レイヤーで描画する（東方の弾らしい見た目）。レイヤーごとにスプライトプールとテクスチャを共有するので、2レイヤーでも各1バッチのまま。レーザーも同じ考え方で、色の帯の中央に白い芯が入る。

## モディファイア

回転 / 重力 / 加速 / 分裂 / フェード / 拡縮 / ランダム / 消滅 / 待機

モディファイアは弾の**年齢**（生成からの経過フレーム）を基準に発火する。エクスポート時は弾 1 発につき 1 本の制御タスク（`TCtrl*`）になる。

## 出力

「出力 / エクスポート」パネルの3タブ。

| タブ | 内容 |
|---|---|
| スクリプト | 東方弾幕風 ph3 (.txt) |
| JSON | プロジェクト (.dmk) |
| CSV | パターン一覧（表計算・差分確認用） |
| GIF | アニメーション GIF（Discord 共有用） |

### GIF 出力

開始・長さ・幅・フレームレートを選んで書き出す。ブラウザ内で完結する（サーバー送信なし）。

- 既定は 400px / 20fps / 4秒 → だいたい 2〜3 MB
- 書き出し後にサイズを表示し、**Discord の上限 10MB** を超えると警告する
- 当たり判定は共有物には不要なので自動的に外れる（グリッドと軌跡は画面の設定にしたがう）
- 「選択中のパターンの範囲にあわせる」でそのパターンの尺にスナップできる
- 保存のほか**クリップボードにコピー**も可能（対応ブラウザのみ）

書き出し中はプレビューの再生が止まり、レンダラをレコーダーが占有する。フレームは決定論的にシミュレーションを巻き戻して描くので、再生中のコマ落ちに影響されない。

ph3 出力の構造:

- `@Initialize` — ボス生成、各タスク起動
- `TMove*` — キーフレーム → `ObjMove_SetDestAtFrame`
- `T<Emitter>_<Pattern>` — `wait` / `loop` / `ascent` + `CreateShotA1` / `CreateShotA2` / `CreateStraightLaserA1`
- `TCtrl*` — モディファイア
- `TLife` — 弾の寿命
- `TFinish` — タイムライン終端で `CloseScript`

`#include "script/default_system/Default_ShotConst.txt"` を前提に `RED01` などの定数を使う。ShotDataID はプロパティで自由に書き換えられる。

## 計測値

本機実測 / Chromium + WebGL（6 emitter × 40 way × 2 layer, interval 4F）:

| 項目 | 実測 | 目標 |
|---|---|---|
| 同時弾数 | 19,968 発（プール上限まで） | 10,000+ |
| 1 フレームの更新 | 0.58 ms | 16.6 ms 以内 |
| スナップショット経由のシーク | 21.8 ms | 100 ms 以内 |
| 編集直後の初回シーク（全再計算・20k 発） | 162.7 ms | — |

デフォルトのプール容量は 12,000 発（`new Simulator(project, capacity)`）。

## 現状の制限

- **Web Worker 未使用。** エンジンは React 非依存の純モジュールとして分離済みで移行は容易だが、実測 0.58 ms/frame とメインスレッドに十分な余裕があるため同期実行。
- **音声はプレビュー専用。** ph3 側はコメントアウトされた `TSound` タスクとして出力する（パスを直して有効化できる）。
- **ボスオブジェクトは 1 つ。** キーフレームを持つエミッターが複数ある場合、出力スクリプトの先頭に警告コメントが入る。キーフレームを持たないエミッターは静的座標（`CX + (x)`）から発射する。
- **`.dmk` に音声ファイルは含まない。** 読み込んだ音源はセッション内のみ有効。
- `分裂` の子弾は再分裂しない（指数爆発の防止）。
- `.dmk` は v2 形式。v1（パターンがトラック配下のクリップだった旧形式）は読み込めない。
